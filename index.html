UnicAthlete Scouting CRM

This page separates the recruiter-facing product experience from the backend architecture. The MVP is organized around professional profiles, workspaces, recruiting projects, athletes, collaboration, project-based evaluation, requests, messages, and comparison.

1. Recruiting UX

What the recruiter/scout experiences in the product.

Open Dashboard→ Choose Workspace→ Open Project→ Discover Athlete→ Add to Project→ Assign Primary Scout→ Evaluate / Request / Message→ Compare / Decide

Dashboard

Shows tasks, request updates, unread messages, assigned athlete updates, and new talent matches across all accessible workspaces.

Open Dashboard

Discover Athletes

Scouts search athletes using filters, apply project criteria, compare candidates, and add athletes to a selected workspace/project.

Open Discover

Workspace

The operational CRM page where scouts manage projects, pipeline stages, athlete ownership, and selected comparison candidates.

Open Workspace

2. Workspace Logic

Workspaces are the top-level operating containers for recruiting work.

Organization Workspace

Owner: Organization owner/admin or head scout.
Members: Multiple scouts with roles and permissions.
Use case: Team recruiting, shared pipeline, shared evaluations, shared requests/messages.
Slate / organization marker

Individual Workspace

Owner: Individual professional/recruiter.
Members: Usually one user, future collaborators possible.
Use case: Private prospects, independent recruiting, personal watchlist.
Purple / individual marker
Workspace markers should appear on project/group cards and mixed views, not repeated unnecessarily on every athlete card.

3. Recruiting Project Logic

Projects/groups are recruiting focuses with criteria, not simple folders.

Project Defines

Objective: Example: U17 Midfielders for 2027 squad.
Criteria: Sport, position, age, gender/category, region, level, class, availability, physical metrics, stats, media, verification.
People: Project owner and assigned scouts.
Work: Athletes, pipeline, evaluations, notes, requests, and decisions.

Athlete Membership

Important: One athlete can belong to multiple projects inside the same workspace.
Example: John Smith can be in U17 Midfielders and Ontario Prospects.
Reason: Different projects evaluate the same athlete against different criteria.
Primary Project: Optional marker for the main recruiting context.
Open Create Recruiting Project

4. Collaboration Logic

Several scouts can work on the same athlete, but responsibility should stay clear.

Primary Scout

One scout responsible for follow-up, pipeline movement, and final recommendation for the athlete inside the workspace/project context.

Accountability

Collaborating Scouts

Additional scouts can evaluate, add notes, request information, review media, message the athlete, and support the decision.

Team Work

Shared Tools

Evaluation Management, Request Management, Messages, and Internal Notes should be shared for assigned scouts to prevent duplicated work.

Shared Context

5. Evaluation Logic

Evaluations are project-specific because scouts evaluate relative to recruiting criteria.

Correct Evaluation Context

Workspace: Toronto Academy
Project: U17 Midfielders
Criteria: Midfielder · Age 15–17 · Ontario · Academy level
Rating: 8.0 / 10 for this project

Different Project, Different Rating

Workspace: Toronto Academy
Project: Ontario Prospects
Criteria: Any position · Ontario · Academy level
Rating: 7.4 / 10 for this project

Open Profile

6. Communication, Requests & Compare

These modules support collaboration and decision-making.

Request Management

Shared request history prevents multiple scouts asking the athlete for the same files or information.

Open Request Management

Messages

Use shared workspace-athlete conversation rather than separate private scout threads.

Open Messages

Compare

Compare 2–4 athletes side-by-side. Best used within project/group criteria context.

Open Compare
