1. Profile Types

The platform is built around two main profile types: Athlete Profiles and Professional Profiles. These two profile types create the foundation of the ecosystem.

Athlete Profile

A structured athlete portfolio that represents the athlete inside the platform. It contains the athlete’s identity, sport information, stats, media, documents, and other materials needed by professionals.

Portfolio Stats Media Documents

Professional Profile

A profile for professionals who work with athletes. Each professional profile has access to a workspace where athlete-related work is organized and managed.

Workspace Projects Athlete Management
Core platform split: athletes present themselves through structured portfolios, while professionals use workspaces to manage their work with athletes.

2. Professional Workspace Access

A Professional Profile can access workspaces in different ways. Depending on how the professional works, they may have an individual workspace, one or more organization workspaces, or both.

Individual Workspace

Used when a professional works independently and manages their own athlete-related work.

Personal

Organization Workspace

Created for an organization and shared by its members for collaborative athlete management.

Organization-Based

Access Management

Organization workspaces are controlled by the Organization Owner and Admins. New members must be approved before gaining workspace access.

Permissions
Professional Profile → Individual Workspace and/or Organization Workspace(s)
Workspace access is flexible: a professional can work independently, through one organization, through multiple organizations, or through both independent and organization workspaces.

3. Workspace Logic

A workspace is where professional work with athletes is organized. Inside a workspace, work is divided into containers. The meaning of a container depends on the professional type. For the MVP recruiter profile, containers are Recruiting Projects.

Workspace

The operating area where a professional or organization manages athlete-related work.

Work Area

Containers

Flexible work units inside a workspace. Their meaning depends on the professional profile type.

Backend Generic

Recruiting Project

For recruiter profiles, each container represents a scouting assignment with specific recruiting criteria.

MVP Container
Workspace → Container → Recruiting Project → Managed Athletes
Backend logic: containers should be generic. For recruiters, the container subtype is Recruiting Project. Future professional types can use different container subtypes without changing the workspace structure.

5. Recruiting Project Work

Each Recruiting Project is one scouting assignment. It contains recruiting criteria, athletes who may fit those criteria, and the collaborative workflow scouts use to make decisions on each athlete.

Recruiting Criteria

The description of the athlete the organization is looking for, such as position, level, age, location, performance profile, media, and other requirements.

Player Target

Managed Athletes

Discovered athletes are added to the project when they may fit the recruiting criteria. The same athlete can belong to multiple projects. Requests and conversations are shared at the workspace-athlete level, while each project keeps its own pipeline, scout assignments, evaluations, and internal notes.

Candidate Pool

Scout Collaboration

Scouts work together on project-specific evaluations, internal notes, and project comparisons, while using shared workspace-level requests and conversations to support recruiting decisions.

Team Workflow

Responsibility Model

Project members collaborate on athletes, but each athlete may have one Primary Scout responsible for coordinating evaluation and making the final recommendation. Additional scouts can participate as collaborators.

Ownership & Collaboration

Ownership & Permissions

Projects are owned by a Project Owner. The Project Owner manages project settings, recruiting criteria, project members, and access controls. Project members can add athletes and work on them, while the Project Owner can override assignments and responsibilities when needed.

Access Control

Primary Scout

The scout responsible for the athlete inside the project. A scout may assign themselves as Primary Scout when adding an athlete, or be assigned by a Project Owner. The Primary Scout manages follow-up, pipeline movement, evaluation coordination, and final recommendation.

Can evaluate: Yes
Can initiate/request info: Yes, through shared workspace requests
Can message athlete: Yes, through shared workspace conversation
Can compare athletes: Yes
Can request collaborator review: Yes

Collaborator Scouts

Scouts who support the Primary Scout on a specific athlete. Collaborators can be added by the Primary Scout or Project Owner to assist with review, evaluation, comparison, and internal discussion.

Can evaluate: Yes
Can review linked request responses: Yes
Can compare athletes: Yes
Can leave internal notes: Yes
Final responsibility: No, Primary Scout owns this
Rules: - NEW can be unassigned. - REVIEWING and later require primary_scout_id. - Project members can add athletes. - Project members can self-assign as Primary Scout when adding an athlete. - Project Owner can override assignments.
