Wireframe rule note: 14-15 supervised accounts

This is a product rule behind the screen, not a user-facing signup field.

Spec note
Account structure
  • Athlete and guardian are separate user accounts.
  • Both accounts are linked to one athlete profile.
  • Each user has their own email and password.
Athlete can edit directly
  • Non-sensitive sport profile information.
  • Stats, position, club/team, achievements, and recruiting media.
Guardian approval required
  • Messages and information request responses.
  • Visibility settings, contact details, protected documents, and sensitive fields.
MVP approval model
  • One generic queue: pending guardian approval.
  • Guardian can approve, reject, or edit before sensitive information is sent, visible, or shared.

Wireframe rule note: 16-17 connected accounts

This explains the product rule behind the 16-17 access choice before either signup path starts.

Spec note
Account structure
  • Athlete and guardian are separate user accounts linked to one athlete profile.
  • Guardian remains connected until adult transfer or explicit relationship change.
Supervised mode
  • Same approval pattern as 14-15.
  • Messages, request responses, and sensitive sharing wait for guardian approval.
Independent mode
  • The starter can request it, but both athlete and guardian must confirm.
  • Athlete can handle scout communication and recruiting information sharing directly only after joint consent.
Consent fallback
  • If either side declines or does not confirm, supervised mode wins.
  • Guardian keeps view access, safety settings, consent controls, adult-transfer controls, and can return independent mode to supervised later.
