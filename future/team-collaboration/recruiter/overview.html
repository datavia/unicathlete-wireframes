Professional Workspace Access

A Professional Profile can access workspaces in different ways. Depending on how the professional works, they may have an individual workspace, one or more organization workspaces, or both.

Individual Workspace

Used when a professional works independently and manages their own athlete-related work.

One-person workspace

Organization Workspace

Created for an organization and shared by its members for collaborative athlete management.

Organization-Based
Professional Profile → Individual Workspace and/or Organization Workspace(s)
Access: Organization Owners and Admins manage workspace membership and permissions.

Workspace Logic

A workspace is where professional work with athletes is organized. Inside a workspace, work is divided into projects. The meaning of a project depends on the professional type. For the MVP recruiter profile, projects are Recruiting Projects.

Workspace

The operating area where a professional or organization manages athlete-related work.

Work Area

Projects

Generic work units inside a workspace. Each professional profile implements its own project type.

Current Project Type (MVP)
Recruiting Project Each project represents a scouting assignment with specific recruiting criteria.
Work Unit
Workspace → Recruiting Project → Managed Athletes
Ownership model: Projects are owned by a Project Owner. The Project Owner manages project settings, recruiting criteria, project members, and access controls. Project members can add athletes and work on them, while the Project Owner can override assignments and responsibilities when needed.

Recruiting Project Work

Each Recruiting Project is one scouting assignment. It contains recruiting criteria, athletes who may fit those criteria, and the collaborative workflow scouts use to make decisions on each athlete.

Recruiting Criteria

The description of the athlete the organization is looking for, such as position, level, age, location, performance profile, media, and other requirements.

Player Target

Managed Athletes

Discovered athletes are added to the project when they may fit the recruiting criteria. The same athlete can belong to multiple recruiting projects.

Candidate Pool

Scout Actions

Scouts work on athletes using both project-specific actions and workspace-shared actions.

Project-specific: Evaluate, compare, internal notes
Workspace-shared: Message, request information
Team Workflow

Primary Scout

Project members can collaborate on athletes, but each active athlete should have one Primary Scout responsible for coordinating evaluation and making the final recommendation.

Primary Scout

The scout responsible for the athlete inside the project. A scout may assign themselves as Primary Scout when adding an athlete, or be assigned by a Project Owner. The Primary Scout manages follow-up, pipeline movement, evaluation coordination, and final recommendation.

Can evaluate: Yes
Can initiate/request info: Yes, through shared workspace requests
Can message athlete: Yes, through shared workspace conversation
Can compare athletes: Yes
Can request collaborator review: Yes

Collaborator Scouts

Scouts who support the Primary Scout on a specific athlete. Collaborators can be added by the Primary Scout or Project Owner to assist with review, evaluation, comparison, and internal discussion.

Can evaluate: Yes
Can review linked request responses: Yes
Can compare athletes: Yes
Can leave internal notes: Yes
Final responsibility: No, Primary Scout owns this
Rules: - NEW can be unassigned. - REVIEWING and later require primary_scout_id. - Project members can add athletes. - Project members can self-assign as Primary Scout when adding an athlete. - Project Owner can override assignments.
