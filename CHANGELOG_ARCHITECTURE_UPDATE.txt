UnicAthlete architecture update

Implemented adjustments across the current HTML wireframes:
- Standardized user-facing language around Workspace -> Recruiting Projects.
- Removed mixed Product Architecture wording such as Container and Project / Group from current pages.
- Clarified ScoutAthleteRelationship vs ProjectAthlete responsibilities in backend notes.
- Added external_status as the athlete-facing opportunity status layer.
- Clarified that pipeline_status is internal and outcome is separate: signed / rejected / withdrawn / archived.
- Added ActivityLog/activity history language so reporting can be supported later without making management reporting an MVP feature.
- Tightened workspace member permissions: Owner, Admin, Scout/Member.
- Updated Discover, Workspace, Create Recruiting Project, Athlete Overview, Recruiter Overview, and top-level architecture notes.
- Restored Scout Profile as the private identity/trust page and moved the Scout Portfolio activity summary to the Dashboard: athletes followed, in pipeline, contacted, and active projects.
- Clarified that the athlete profile is the only public showcase profile; scouts work behind the scenes through private workspaces and project contexts.
- Added MVP screening model: scouts save athletes to a project-level Saved Athletes longlist from Discovery, then promote selected athletes into Pipeline New. Saved Athletes can be filtered by All Saved, Not in Pipeline, and In Pipeline.
- Added cross-cutting preservation principle: nothing is lost unless the user explicitly chooses permanent delete; Saved Athletes, pipeline history, notes, evaluations, and archived projects remain available or recoverable by default.
- Added shared signup flow map and age-based athlete account specification: signup now starts with profile-type selection, athlete onboarding branches by profile manager/date of birth, under-14 profiles are guardian-managed, and later age transitions are specified for 14, 16, and 18.
